# 必须保留的内容与公开发布边界

用户确认：GitHub保留源码+安装包，清理无关内容。整理不授权删除本地资料、玩家数据或历史Release。

## 不可随意改动

| 对象 | 规则 |
|---|---|
| com.smallphone.app、APK历史签名、https://small-phone.local/ | 升级身份与数据空间，变更必须单独迁移方案；不能重新签名后让玩家卸载 |
| char-phone-framework、图片库、xiaophone://image/、persist迁移 | 兼容旧备份；本次版本78；不能删除历史迁移来“精简” |
| 1.16.1临时数据找回入口 | 在旧区导出/迁移可验证前保留；不可偷偷清空旧区 |
| 玩家聊天/角色/人设/图片/备份/预设 | 默认不清理、不覆盖、不上传公开仓库 |
| approved主题、现有素材与许可 | 不按文件名猜无用；例如public/p5-reference-home.jpg仍被CSS引用，必须保留 |
| 原生工程、签名相关本地文件、锁文件 | android-local-backup虽然名字像备份，仍含构建所需内容；不批量删除或更换 |
| 总计划、NEXT、模块说明、原始历史资料 | 更新可追踪；移除公开追踪时保留本地并留清单；删除前有可恢复副本 |
| 原有未提交设计稿/截图 | 本轮原样保留，不用git clean、不覆盖、不顺带提交 |

## 发布分类

| 内容 | 本地 | GitHub源码 | 安装包/Release |
|---|---|---|---|
| src/api/server、配置、锁文件、测试/构建脚本、运行资源、许可证 | 保留 | 保留 | 仅构建所需资源进入软件 |
| 当前总计划/目录说明/公开教程/版本公告 | 保留 | 可公开，无个人坐标/秘密 | 仅必要说明和公告 |
| docs/superpowers、旧work-log、阶段截图与验证记录、恢复的旧交接 | 保留 | 退出当前树/不新上传 | 不上传 |
| designs、主题美化、气泡美化、docs/tasks | 保留原件 | 不新上传设计过程资料 | 仅认可且实际引用的成品资源 |
| .env、用户导出、运行data、调试日志、缓存、真实凭据 | 保留在既有安全位置 | 禁止 | 禁止 |
| APK | 本地交付 | 不入源码历史 | 仅Release附件 |

历史Git提交不重写，旧Release不删除；从当前树去掉文件不等于从历史彻底抹除。若未来发现秘密，应另行轮换与处理，不用本轮普通整理掩盖。

## 上传流程

1. 查git status，保留原有未提交内容；只按明确路径暂存，禁止git add .打包全目录。
2. 执行node scripts/check-public-files.mjs --staged；检查当前树可用--tracked。脚本检查文件范围、总计划等必需入口和源码目录README，误移除时阻止发布；不宣称扫描所有秘密。
3. 更新CHANGELOG，功能版还需中文Release公告、版本/签名/内置网页验证；文档整理不伪造新APK版本。
4. 源码提交只含软件相关文件。node scripts/prepare-release-files.mjs --apk <明确路径> --notes <公告> --out <新输出目录> 只复制指定APK、公告和校验清单，不遍历工作区；此脚本不上传且不代替签名检查。
5. 推送前看精确差异；发布后回读远端SHA、附件名/大小/哈希。保留上一个可安装版本。

## 文档维护

主要维护目录的README说明职责、真实文件和禁止事项；资源叶目录以父级索引和许可证为准，依赖、构建缓存不放人为维护文档。新增软件应同时新增目录README并登记总表，不能新造平行进度表。
