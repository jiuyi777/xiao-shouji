# 数据保存、账号与VPS通知方案

更新：2026-10-10；方案文档，未实施项以总表为准。

## 两份数据的确切来源

mobile-export/App.js 同时保留稳定来源 https://small-phone.local/ 和 BROKEN_V1161_STORAGE_ORIGIN=file:///android_asset/。浏览器按来源隔离localStorage/IndexedDB，1.16.1更换来源造成两套数据。BackupScreen已有“查看1.16.1临时数据→导出→返回旧数据→安全合并”的入口。本轮没有读写玩家设备上的任何一份数据。

这不同于有意把文字和图片分开存：主状态char-phone-framework在localStorage；图片xiaophone-image-assets在IndexedDB，以xiaophone://image/引用；语音缓存与辅助键另存。它们应属于同一个逻辑存档，通过备份清单关联，不应粗暴塞回一条巨大JSON。

## 现有缺口

1. 导出图片失败会被catch转成空对象；完整备份可能只保住文字引用，没有图片。
2. 同ID的合并默认当前值胜出，保护当前内容但可能遗漏另一份中更新的文本；需要冲突预览，不宣称现在按修改时间合并。
3. 主状态提交失败可以回滚localStorage；图片先写入，整体还不是跨存储原子事务，需要导入暂存与新增资产回滚记录。
4. 现有导出包含主状态、图片和两个辅助键；语音缓存没有在这条导出链显式导出，不能称所有媒体均可恢复。
5. 备份可能包含用户填写的接口配置，云端/分享前需要区分“私人完整备份”和“不含密钥的分享导出”，不得把用户备份上传公开仓库。

## 建议的保存合同

| 数据 | 当前权威 | 后续方案 | 禁止做法 |
|---|---|---|---|
| 角色/聊天/人设/预设/生活事件 | 本机主状态 | 稳定ID、schemaVersion、存档ID、变更版本；迁移前快照 | 改包名/来源当成升级，整包覆盖旧数据 |
| 图片/必要媒体 | 本地资产库+引用 | 备份manifest列数量、字节数、哈希；先验证资产再确认导入 | 引用存在就说图片恢复成功 |
| 可再生缓存 | TTS缓存等 | 明确“包含/不包含”，必要时可选导出 | 静默删除玩家保存的原始媒体 |
| 真人账号/好友关系 | 尚未建立 | VPS账号与关系表，clientId只标识设备 | 把角色id、User人设或设备id当登录凭据 |
| 私人角色数据 | 本地 | 默认不共享；未来按玩家授权备份/同步 | 加好友后自动读对方角色私聊 |
| 在线棋谱/落子 | 尚未建立 | 服务端权威房间版本和去重moveId，本地缓存 | 客户端自行宣告胜负并覆盖对方 |
| 通知任务 | 当前服务端JSON | 持久队列、归属、幂等键、重试状态、送达/已读区分 | HTTP成功当成设备已显示 |

恢复顺序：保留两份原始导出→识别来源与版本→校验图片清单→显示新增/冲突→暂存导入→提交→刷新内存→重开抽查原文/图片→用户确认后才能手动清理旧区。

云端分两步：先提供可选加密快照备份和恢复，再实施多设备增量同步。同步需要对象版本、删除标记、服务端修订号、离线操作队列与冲突选择；不能以“最后上传整包覆盖”实现。密钥保存/找回方案应先定，不假定服务器可读取私人角色聊天。

## VPS复用与通知

已有server/nai-proxy.cjs提供生图/TTS代理与提醒路由；server/proactive-reminders.cjs将提醒、outbox、设备写入JSON。APK已有expo-notifications、token桥和本地提醒。可以继续用既有VPS运行独立服务，不要求新买服务器。

上线前需补：登录与设备绑定、所有权校验、频率限制、事务数据库/队列、进程守护、HTTPS、日志轮转、持久卷与恢复演练。推荐先单节点数据库方案；多人/并发同步增长后采用PostgreSQL，选型取决于实际VPS资源，不先堆Redis/微服务。

当前提醒注册/outbox/ACK信任调用方clientId，不能直接作为公开多人服务。当前发送Expo仅处理提交结果，未看到后续receipt查询。需要ticket→receipt轮询、失效token停用、失败重试与业务去重。通知运输可按回退策略重试，付费AI生成仍不自动重试。

VPS只能负责调度与发送，Android后台显示仍依赖系统权限与推送通道。Expo/FCM适配与无Google服务设备需分别真机验证；应用离线时下次打开补拉outbox。默认推送只含简短提示，敏感正文不直接出现在锁屏。

部署先做只读盘点：确认现有VPS、域名、可用内存/磁盘、数据库与备份位置、端口冲突及FCM凭据是否已配置。当前未连接生产VPS，不能填写“已部署”。不得改动同机其他bot/代理/站点。测试通知只发专用测试设备。

## 游戏与好友最小闭环

推荐五子棋，棋种仍待用户决定。规则引擎负责合法步、胜负与难度；角色语言模型只做点评或参与候选步选择，输出必须再次校验，不能让文字生成器充当裁判。第一版保存完整棋谱，可暂停续局。

真人功能从好友码、请求、接受/拒绝、拉黑、移除开始；真人会话与角色会话清楚分开。好友只允许读取主动公开的资料。在线棋局用服务端落子顺序与房间版本，断线后先补拉棋谱再操作。是否首版附真人私聊尚未决定。

## 验证清单

- 数据：旧/新区各有独有记录和同ID冲突；重复导入、空间不足、图片失败、应用重开。
- 账号：两账号/两设备隔离，伪造clientId不能访问别人的任务、好友和棋谱。
- 通知：前后台、拒绝权限、离线、token失效、服务器重启、重复投递、点击定位。
- 棋局：越界、重复落子、非本方回合、胜负、悔棋、双方同时操作、断线重连。
- 云同步：双方同时编辑和删除，断网后补发，冲突保留两版，恢复可回滚。
